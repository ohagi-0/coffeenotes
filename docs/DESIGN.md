## 1. デザイン原則

コンセプト名は **Espresso & Copper**。深煎り豆の色を地にして、銅のケトルの色を一点だけ置く。

| # | 原則 | 実装で守ること |
|---|---|---|
| P1 | カードの言葉をそのまま使う | 豆名・ロースター名・フレーバーは英字のまま保持し、翻訳しない。豆名は Bodoni Moda で大きく、数字（標高・価格・比率・星）は Manrope で主役に。日本語はラベルと説明に回す |
| P2 | 銅色は操作できる場所だけ | 銅（`--cu`）を使ってよいのは ＋ボタン、主ボタン、星、選択中タブ、リンク、選択中の枠線。装飾・見出し・区切り線には使わない。要確認は琥珀、削除と失敗は錆色で銅と混ぜない |
| P3 | 片手で、親指で | 主操作は画面下 1/3。タップ領域 44px 以上。画面に主ボタンは 1 つ。詳細（レシピ・焙煎）は折りたたみ、星とメモだけで保存できる |
| P4 | 3 状態を必ず持つ | 読み込み・空・失敗（+ 成功トースト）の無い画面はレビューで差し戻す（CLAUDE.md §5.3） |
| P5 | ダーク専用 | ライトテーマは実装しない。`color-scheme: dark` 固定。OS 設定は見ない（ADR 0006） |

## 3. 共通レイアウト

Web スマホ版は「アプリ」ではなく「スマホ向け Web サイト」の作法で組む（ADR 0007 追記）。下タブは iOS アプリ版だけが持つ。

- 基準幅 375px。767px までは 1 面。768px 以上のレイアウトは §9.1（ADR 0007）。
- サイトヘッダー（sticky、高さ 56px、下に 1px の `--line`）: 左にワードマーク（display 22px）、右に「＋ 記録する」（銅のピル、高さ 36px）とメニューボタン（44px）。ウィザード中は「＋ 記録する」の代わりに「やめる」リンク。
- メニュー: ヘッダー右のボタンで右から開くドロワー（幅 82%）。項目はページ名そのまま: 入力記録一覧 / 豆のコレクション / 記録したお店 / 好みの分析 / 設定、「記録を追加」ボタン、最下部にアカウントとログアウト（地図は 2026-09-24 に「記録したお店」へ統合、豆のコレクションは同日に追加）。一文字の略称（「店」「地図」）は使わない。PC のサイドバーも同じ文言。iOS の下タブだけ短縮形（ホーム / 棚 / お店 / ＋ / 好み / 設定 のうち 5 つ）。
- 画面タイトルはヘッダーの下に UI 700 / 24px。詳細ページはタイトルの代わりにパンくず（`入力記録一覧 › 豆`）と右端の「編集」リンク。ウィザードは 3 段のステッパー（撮影 / 確認 / 店と評価。済みと現在は銅の上線）。
- フッター: 各ページの末尾に小さく 2 行（上に 1px の `--line`）。1 行目にワードマーク（15px）とページへのリンク、2 行目に © · プライバシー · 利用規約 · お問い合わせ（GitHub の Issue、別タブ）。11px。
- 戻るはブラウザの戻る。画面内に独自の戻るボタンは置かない。各画面は共有できる URL を持つ。
- 地図は「記録したお店」（S6）の上部、ページ内の 300px の枠に置き、選んだ店のカードと一覧はその下に普通に流す。ボトムシートは使わない。
- 撮影は OS のカメラ（`<input capture>` 相当を `src/lib/platform/camera.ts` 経由で）。表と裏のタイルに「カメラで撮る / 写真を選ぶ」。
- iOS アプリ版のナビは §9.3（下タブ + 大タイトル）。同じナビ定義から、Web ではヘッダー + ドロワー、ネイティブでは下タブを描く。

## 5. 画面仕様

各画面は「要素 / 状態 / 遷移 / 要件 ID / フェーズ」で書く。フェーズは REQUIREMENTS.md §10。

### S1 ログイン `/login` — Phase 0

- 要素: ワードマーク（display 64px、画面下寄せ）、タグライン、「Google で続ける」（白ボタン）、メール入力 + 「ログインリンクを送る」（二次ボタン）、注記「パスワードはありません…」。
- 状態: 送信中（ボタンをスピナーに）、送信完了（「リンクを送りました。メールを開いてください」に置き換え）、失敗（錆色のコールアウト）。
- 遷移: 成功 → S2。ログイン済みなら `/login` に来ても S2 へ。
- 要件: F-AUTH-1。

### S2 入力記録一覧 `/logs` — Phase 1（2026-09-24 にホームから移動。ホームは S10）

- 要素: サイトヘッダー、タイトル「入力記録一覧」+ 今月の杯数、検索欄（常設）。絞り込みチップ（絞り込み / すべて / 星 4 以上 / 自宅 / 生産国 / 精製 / タグ）。日付見出し（「今日 · 9月21日（日）」）でグループ化したログ行。
- 状態: 読み込み（ログ行のスケルトン 4 件）、空（「まだ記録がありません」+「最初の記録を追加」）、失敗（コールアウト + 再読み込み）、絞り込み結果 0 件（「条件に合う記録はありません」+ 絞り込みを解除）。
- 遷移: ログ行 → S5。検索欄はフリーワード検索（Phase 5 の F-LIST-3、それまでは非表示）。ヘッダーの「＋ 記録する」→ S3 入口。
- 検索: 検索欄「豆名・フレーバー・メモ・店名で探す」。空白区切りの語をすべて含む記録だけ残す（手元で絞る。`?q=` に持ち共有・戻るに対応）。チップと併用可（F-LIST-3）。
- 一括削除: タイトル右の「選択」で選択モード。行がチェックボックスになり、下に固定のバー（N 件を選択中 / すべて選択 / 削除）。「削除」→ 確認ダイアログ「N 件の記録を削除しますか？ 豆の情報とカード画像は残ります」→ トースト「N 件の記録を削除しました」（F-LOG-7）。
- 要件: F-LIST-1 / F-LIST-2 / F-LIST-5。

### S3 記録作成ウィザード `/logs/new` — Phase 1（撮影・OCR は Phase 2）

**入口（`/logs/new`）**
- 要素: ヘッダー（「やめる」）、タイトル、「テイスティングカードから読み取る」（銅）、「手で入力する」、「登録済みの豆から」の 3 択。下に「最近の豆」3 件。「登録済みの豆から」を押すと同じ画面が過去の豆の選択に切り替わる（検索欄: 豆名・ロースター・生産国、新しい順の全件、「入口に戻る」）。
- 遷移: 撮る → ①、手入力 → ②（空フォーム）、登録済み → 豆検索 → ③。最近の豆をタップ → ③。
- 要件: F-LOG-1 / F-BEAN-15 / UC6。

**① カード撮影（Phase 2）**
- 要素: ステッパー（1 撮影）、表のタイル（撮影済みならサムネイル + 撮り直す）、裏のタイル（任意。「カメラで撮る」「写真を選ぶ」）、主ボタン「この内容で読み取る」、注記「長辺 1,600px に縮小」。Web はアプリ内カメラを持たず、OS のカメラを起動する。
- 状態: 表が未撮影なら主ボタンは無効。カメラ権限拒否 → 「写真を選ぶ」だけを残して説明。アプリ内のガイド枠と連続撮影は iOS 版のみ（§9.3）。
- 実装: `components/logs/capture-step.tsx`。`src/lib/platform/camera.ts` 経由で OS のカメラ／写真選択を開き、撮影後 `src/lib/image/compress.ts` で長辺 1,600px。画像は data URL で sessionStorage に置いて ② へ渡す。
- 要件: F-OCR-1 / F-BEAN-12。

**② 読み取り結果の確認・修正 / 手入力フォーム**
- 要素: ヘッダー（「やめる」）、タイトル、ステッパー（2 確認）、注記 + 「手入力に切り替える」リンク、表裏画像（2 列）、フィールド: 豆名（必須）/ ロースター（任意。共通マスタから補完。空なら付けない）/ 生産国・標高 / 地域 / 品種・精製 / フレーバー（タグ入力、+ 追加）/ 味覚チャート / 価格・入手区分 / 説明文。主ボタン「次へ：どこで飲んだ？」。
- 状態: OCR 実行中（画像を残したままスケルトン + 進捗バー「通常 3〜8 秒」+「スキップして手入力する」。10 秒を超えたら「時間がかかっています（最大 30 秒ほど）」の案内に変わるが、自動では手入力に落とさない。2026-09-24）、OCR 失敗（コールアウト「文字が判別できませんでした」+ 撮り直す / 手で入力する。画像は保持）、必須未入力（豆名の下に錆色の 1 文）。
- 実装: `/logs/new?step=ocr`。`features/ocr/extract-bean-card.ts` で `/api/ocr` を呼び、`extractionToBeanForm` で `BeanForm` の `defaultValues` と `confidence` に流すだけ。`BeanForm` は `confidence` のある項目を `OcrField` で描く。上限超過（429）・無効（503）・10 秒超過は同じ画面で手入力に切り替え、画像は保持する。
- 要件: F-OCR-2 / F-OCR-5 / F-OCR-6 / F-BEAN-1〜11。

**③ 場所・日付・評価・メモ**
- 要素: ヘッダー（「やめる」）、タイトル、ステッパー（3 店と評価）、セグメント（店で / 自宅で）。

## 6. 状態と文言のルール

| 状態 | 見せ方 | 文言 |
|---|---|---|
| 読み込み | 内容と同じ形のスケルトン。全面スピナーは認証確認のときだけ | なし |
| 空 | 丸アイコン + 見出し + 1 文 + 主ボタン 1 つ | 行動への招待。「まだ〜がありません」+ 次にできること |
| 失敗 | 錆色のコールアウト、入力内容は保持 | 何が起きたか 1 文、次にできること 1 文。謝罪語・曖昧語を使わない |
| 成功 | 上部トースト 3 秒 | ボタンと同じ動詞:「保存する」→「保存しました」、「削除」→「削除しました」 |
| 破壊操作 | 錆色の枠線ボタン + 確認ダイアログ | 何が消えて何が残るかを書く |

文体: 敬体、簡潔、能動。ボタンは「何が起きるか」を書く（「送信」ではなく「ログインリンクを送る」）。
