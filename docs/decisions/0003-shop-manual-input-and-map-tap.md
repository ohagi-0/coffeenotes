# 0003: 店の手入力と地図タップでの位置指定を Must にする

- 日付: 2026-09-21
- ステータス: 決定
- 関連要件: F-SHOP-3, F-SHOP-4, F-SHOP-6, F-SHOP-7（REQUIREMENTS.md §8.2）

## 背景

店候補の取得元として Google Places と OpenStreetMap（Nominatim / Overpass）を比較した。どちらでも出てこない個人店があり、候補検索だけに頼ると店を登録できないケースが残る。

## 選択肢

1. Google Places を使い、候補検索を主経路にする
2. Nominatim（無料・キー不要）を使い、候補検索を主経路にする
3. 候補検索は入力補助と位置づけ、手入力 + 地図タップを Must にする

## 決定

3 を採用し、候補検索はまず Nominatim で作る。店の登録は「①候補から選ぶ → ②手入力 + 住所から座標 → ③手入力 + 地図タップ」の 3 段構えとし、どの段でも座標付きの店が作れることを保証する。座標が無い店も保存可（地図には出さず一覧のみ）。`GeoProvider` 抽象化を維持し、精度に不満が出たら Google Places に差し替える。

## 理由

候補検索の網羅性はどの API でも完全にはならない。手入力と地図タップを Must にすれば候補検索が失敗しても登録が完結し、API 選定を後から変えられる。Nominatim は無料でキー不要のため初期コストが最小。Google Places の無料枠（月 10,000 回、2026-09 確認）は個人〜数十人規模なら超えない見込みで、差し替えの障壁は低い。
