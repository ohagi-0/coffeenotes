# 0001: OCR エンジンは Claude Haiku 4.5 Vision

- 日付: 2026-09-21
- ステータス: 決定
- 関連要件: F-OCR-2, F-OCR-3, F-OCR-5, F-OCR-6（REQUIREMENTS.md §8.1）

## 背景

テイスティングカードの読み取りは「文字を読む」だけでなく、Region / Flavor などの項目への振り分け、日本語説明文と英語項目の混在、味覚チャートのドット（塗り／未塗り）の判定が必要。方式によって得意・不得意が分かれる。

## 選択肢

|                 | A. LLM Vision（Claude Haiku） | B. Google Cloud Vision | C. Tesseract.js（ブラウザ内） |
| --------------- | ----------------------------- | ---------------------- | ----------------------------- |
| 項目振り分け    | モデルが行う                  | 自前パーサ             | 自前パーサ                    |
| 味覚チャート    | 読める見込み                  | 不可                   | 不可                          |
| 実装工数        | 小                            | 中                     | 中                            |
| 月 100 枚の費用 | 約 75 円                      | 0 円                   | 0 円                          |

## 決定

A. Claude Haiku 4.5 Vision を採用する。モデル `claude-haiku-4-5`、表・裏を 1 リクエスト、`tool_use` で Zod スキーマ相当の JSON を強制、`max_tokens` 1,024、タイムアウト 15 秒。API キーは `/api/ocr` からのみ使い、1 ユーザー 1 日 50 回の上限を置く。`OcrProvider` 抽象化（F-OCR-6）は維持し、`beans.ocr_raw` に生出力を保存する。

## 理由

個人〜数十人規模では方式間の費用差が月数百円未満で誤差の範囲。差が出るのは精度と工数で、A が最も工数が小さく、味覚チャートや日本語説明文まで一度に構造化できる。B はロースターごとにパーサ保守が発生し、C は斜め撮影に弱く「結局手で直す」になりやすい。費用が問題になった段階で `OcrProvider` の差し替えで移行できる。

出典: Anthropic 料金表（Haiku 4.5: 入力 $1 / 出力 $5 per 100 万トークン、2026-09 確認）、Google Cloud Vision 料金（月 1,000 枚まで無料、2026-09 確認）。
