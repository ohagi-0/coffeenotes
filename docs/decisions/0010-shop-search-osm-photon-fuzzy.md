# 0010 店名検索は OSM のまま、周辺の店の一括取得 + 端末でのあいまい照合 + Photon にする

日付: 2026-10-19

## 背景

記録作成の「店を選ぶ」で、店名で検索してもほとんど店が見つからないという指摘があった（2026-10-19、改善依頼）。

- 店名検索は Nominatim（住所・地名向けのジオコーダ）だけで、完全一致に近い名前しか当たらなかった。
- OSM 上の店名は英字だけ（Fuglen Tokyo）、カタカナだけ（スターバックス）などまちまちで、看板どおりカタカナで打っても英字名の店に当たらない。
- 店名検索に現在地を使っておらず、遠くの同名店が混ざる。

調べると、OSM のデータ自体は足りていた。渋谷駅の周囲 1.5 km に、名前付きのカフェ・コーヒー店が 360 件あった（Overpass、2026-10-19）。外れの原因はデータの量ではなく、照合の仕方だった。

## 選択肢

| 案 | 内容 | 評価 |
|---|---|---|
| A. Google Places に切り替え | Text Search / Nearby Search | ヒット率は最も高い。ただし規約で Places の結果を Google 以外の地図に出すことは禁止（Maps Service Terms 5.3）。緯度経度の保存も 30 日まで（5.4）。このアプリは Leaflet + OSM の地図に店のピンを出し、`shops.lat/lng` に座標を保存して使い続けるので、地図ごと Google に替えない限り使えない |
| B. Foursquare Places API | 店の POI 検索 | 無料枠は月 500 回で、超えると 1,000 回あたり 15 ドル（公式の料金ページ、2026-10-19 確認）。入力のたびに検索すると数十人でもすぐ超える。API キーと環境変数の追加も要る |
| C. OSM のまま照合を作り直す | 周辺の店を別名つきでまとめて取り、端末であいまい照合。店名検索は部分一致に強い Photon | 費用 0 円、キー不要、既存データ（`external_place_id` の "node/123" 形式、座標）と完全に互換。OSM に載っていない個人店は出ない（手入力で補う） |

## 決定

C を採る（ADR 0003 の「まず OSM」を維持）。

- **近くの店**: 検索シートを開いたら現在地を取り、Overpass で半径 2 km のカフェ・コーヒー店を最大 300 件、別名（`name:en` / `name:ja-Hira` / `brand` など）つきで取る。サーバーで 10 分間、約 100 m 四方の単位で使い回す。
- **Overpass が落ちているとき**: 本家（overpass-api.de）が混雑や接続エラーなら予備（overpass.private.coffee）を 1 回試す。同時に Photon の周辺検索（最大 50 件・別名なし）も投げておき、Photon が返ってから 2 秒待っても Overpass が返らなければ Photon の結果を使う。2026-10-19 の時点では Overpass の本家・予備とも応答が無く、この切り替えで出ていた。
- **端末でのあいまい照合**（`src/lib/geo/match.ts`）: 次の順に点を付ける。完全一致、部分一致（全角半角・大文字小文字・ひらがなとカタカナ・空白や記号の違いを無視）、子音の骨格の一致（カタカナ ⇄ 英字。フグレン ⇄ Fuglen、ブルーボトル ⇄ Blue Bottle、スタバ ⇄ Starbucks）。骨格の一致は誤爆を防ぐため、3 子音以上で、名前のどこかの語の頭から一致する場合だけ当たりにする。
- **店名検索**: Photon（`photon.komoot.io`）に現在地とカフェのタグを付けて投げる。入力途中の語でも部分一致で当たり、近い店が先に出る。検索語がかなだけのときは、ローマ字にした語（フグレン → fuguren）でも引いて結果をまとめる。Photon が落ちていれば Nominatim に切り替える。
- **住所 → 座標**（「自分で登録する」）は Nominatim のまま。
- 一覧は「近くで当たった店 → 店名検索の結果」の順に、重複を除いて 1 つにまとめる。候補には店名・住所・現在地からの距離を出す。
- 地図の候補から作る店は、同じ OSM の ID の店が自分の店にあればそれを使う（二重登録しない）。

## 理由

- データは OSM に十分あり、外れの原因は照合だった。照合を直せば費用 0 円で改善できる。
- Google は今の地図と規約上組み合わせられない。Foursquare は無料枠が小さく、入力ごとの検索に向かない。
- 周辺の店をまとめて取って端末で絞るので、1 文字打つたびにサーバーを叩かない。公開サーバーへの負荷も下がる。
- 既存の店データ（`external_place_id`、座標）の形は変わらない。DB の変更も無い。

## 残る課題

- OSM に載っていない個人店は出ない。従来どおり「自分で登録する」（店名 + 住所）で登録する（F-SHOP-6）。
- Overpass が落ちている間は、近くの店が Photon の 50 件に減り、別名も無くなる。そのため、カタカナから英字名の店へ当たるのは、近くの 50 件とローマ字検索で当たる店だけになる。
- 公開サーバー（Overpass / Photon / Nominatim）の可用性には保証が無い。止まっても手入力で店を作れるので、記録はできる。
- それでも精度に不満が出たら、地図を Google Maps に替える前提で A を、または B を見直す。
