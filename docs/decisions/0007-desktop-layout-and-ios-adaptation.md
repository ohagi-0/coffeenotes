# 0007: PC は 3 列レイアウトで「振り返る」、iOS は同じ UI に OS の作法だけ足す

- 日付: 2026-09-22
- ステータス: 決定
- 関連要件: §5 画面構成、§6 非機能要件（対応環境）、§13 ネイティブアプリ化、F-LIST-1〜5、F-MAP-1〜4、F-STAT-1〜4、F-OCR-1

## 背景

要件定義書 §6 は「PC ブラウザは閲覧のみ動作保証」としていたが、ユーザーから Web スマホ版に加えて Web PC 版と iOS アプリ版の画面設計を求められた。振り返り（UC3・UC5）は画面が広いほど楽で、統計や地図は PC の方が向く。一方 iOS 版は §13 のとおり Capacitor で同じコードを包むため、別デザインを起こすと二重保守になる。どこまで差をつけるかを決める必要があった。

## 選択肢

### PC 版

1. スマホ版をそのまま中央に置く（閲覧のみ。§6 の最低保証どおり）
2. 幅に応じて列数とナビの位置だけ変える 3 列レイアウト。撮影以外の全機能を PC でも使える
3. PC 専用の別アプリ（管理画面寄り）

### iOS 版

- A. PWA と同じ UI に、OS の作法（大タイトル、アクションシート、コンテキストメニュー、ハプティクス）と iOS でしかできない入口（共有シート、アプリ内連続撮影）だけを足す
- B. iOS ネイティブ風に全画面を作り直す

## 決定

- PC 版は **2**。ブレークポイントは 768px（下タブ → 左のアイコンレール）と 1,280px（ラベル付きサイドバー 236px + 一覧 400px + 詳細）。記録の追加はモーダルで、入口は「写真をドロップ」「手入力」「登録済みから」。カメラ撮影は PC では提供しない。
- iOS 版は **A**。差分は `src/lib/platform/` のラッパーで切り替え、UI コンポーネントは OS 分岐を持たない。変えるのは次の 7 場面: アイコンと起動画面、大タイトル、共有シートからの登録、写真の取り込み（表裏の割り当て）、アプリ内カメラの連続撮影、長押しのコンテキストメニュー、削除のアクションシート。
- REQUIREMENTS.md §6 の対応環境を「PC は 1,280px 以上で 3 列。撮影は非対応」に改める。
- モックは `docs/design/` を 4 ページに分け（方針 / Web スマホ / Web PC / iOS）、共通 CSS・JS を共有する。

## 理由

- **PC 2 を選んだ理由**: 1 では画面幅が無駄になり、統計・地図の価値が出ない。3 は保守対象が増える。2 なら同じコンポーネントを CSS グリッドで並べ替えるだけで、Tailwind のブレークポイントで実装できる。撮影を外したのは、PC のカメラでカードを撮る場面が現実に無いため。
- **iOS A を選んだ理由**: B は Capacitor の利点（書き直さない）を捨てることになる。A で足す 7 場面は、いずれも「ストア版を入れる理由」（共有シート、連続撮影）か「OS に任せた方が説明が要らないもの」（アクションシート、コンテキストメニュー）で、UI の見た目は変えない。
- **共有シートを最重要に置いた理由**: §13.1 で PWA が唯一できないと明記した機能で、店でカードを撮った後の導線が「写真を開いて共有」の 2 タップになる。これが App Store 版の差別化になる。
